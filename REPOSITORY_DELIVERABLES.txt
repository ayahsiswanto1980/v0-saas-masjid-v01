================================================================================
                              ARCHITECTURE
================================================================================

LAYER STRUCTURE:
┌─────────────────────────────────────┐
│ Presentation Layer (React)           │ No data awareness
├─────────────────────────────────────┤
│ Service Layer (Business Logic)       │ Depends on interface
├─────────────────────────────────────┤
│ Repository Layer (Data Access)       │ Interface + implementations
├─────────────────────────────────────┤
│ Data Source (IndexedDB or API)       │ Swappable via config
└─────────────────────────────────────┘

DEPENDENCY DIRECTION:
Component → Service → IMosqueRepository → IndexedDBRepository OR APIRepository

KEY DESIGN PATTERNS:
1. Repository Pattern (abstraction)
2. Dependency Injection (loose coupling)
3. Factory Pattern (configuration-based creation)
4. Strategy Pattern (swappable implementations)
5. Simple IoC Container (service management)
6. Provider Pattern (React integration)

TYPE SAFETY:
- Full TypeScript throughout
- No implicit 'any' types
- Compile-time checking
- Runtime validation with type guards

MULTI-TENANT SUPPORT:
- Tenant context management
- All queries include tenantId
- Data isolation enforced
- No cross-tenant leaks

USAGE IN COMPONENT:
import { useMosqueService } from './providers/RepositoryProvider'

function MosqueList() {
  const service = useMosqueService()
  
  useEffect(() => {
    service.setTenant(tenantId)
    service.listMosques().then(({ items }) => {
      setMosques(items)
    })
  }, [])
}

SWITCHING DATA SOURCE:
// Change config to use API
const config = {
  dataSource: 'api',
  apiConfig: {
    baseURL: 'https://api.yourdomain.com',
    getToken: () => localStorage.getItem('authToken')
  }
}

// NO COMPONENT CHANGES NEEDED! 🎉
