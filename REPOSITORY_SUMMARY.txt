================================================================================
                            KEY DESIGN PATTERNS
================================================================================

1. REPOSITORY PATTERN
   • Abstraction of data source
   • Interface: IMosqueRepository
   • Implementations: IndexedDB, API
   • Benefit: Swappable data sources

2. DEPENDENCY INJECTION
   • Constructor injection in service
   • Service depends on interface, not concrete class
   • Easier testing & mocking
   • Reduces coupling

3. FACTORY PATTERN
   • createMosqueRepository() function
   • Creates correct implementation based on config
   • Centralized instance creation
   • Single change point for switching

4. STRATEGY PATTERN
   • Repository acts as strategy
   • MosqueIndexedDBRepository vs MosqueAPIRepository
   • Same interface, different algorithms
   • Runtime selection based on config

5. SIMPLE IOC CONTAINER
   • Manages service instances
   • DIContainer class with registry
   • Manual DI (not framework-dependent)
   • Easy to understand & debug

6. PROVIDER PATTERN (React)
   • Context API for dependency provision
   • useMosqueService() hook
   • No prop drilling
   • Clean component interfaces

================================================================================
                          MIGRATION WORKFLOW
================================================================================

BEFORE (IndexedDB Only):
├─ Component calls useMosqueService()
├─ Service validates input
├─ Repository.create() called
├─ MosqueIndexedDBRepository stores locally
├─ SyncQueue tracked
└─ Sync happens when online

AFTER (API Only):
├─ Component calls useMosqueService() [NO CHANGE]
├─ Service validates input [NO CHANGE]
├─ Repository.create() called [NO CHANGE]
├─ MosqueAPIRepository makes HTTP request
├─ Data stored on server immediately
└─ No client-side sync needed

STEP-BY-STEP MIGRATION:
  1. Prepare backend API (Laravel)
  2. Implement all endpoints (/api/mosques/...)
  3. Change 1 config line: dataSource = 'api'
  4. Initialize with apiConfig
  5. Done! Zero component changes needed!

TIME TO MIGRATE: 1-2 hours
RISK LEVEL: Very low (can rollback immediately)
COMPONENT CHANGES: Zero

================================================================================
                             CONFIGURATION
================================================================================

SETUP IN main.tsx:

import { RepositoryProvider } from './providers/RepositoryProvider'

// For development (IndexedDB)
const config = {
  dataSource: 'indexeddb'
}

// For production (API)
const config = {
  dataSource: 'api',
  apiConfig: {
    baseURL: 'https://api.yourdomain.com',
    timeout: 30000,
    getToken: () => localStorage.getItem('authToken')
  }
}

ReactDOM.createRoot(document.getElementById('root')!).render(
  <React.StrictMode>
    <RepositoryProvider config={config}>
      <App />
    </RepositoryProvider>
  </React.StrictMode>
)

ENVIRONMENT VARIABLES:

.env.development:
VITE_DATA_SOURCE=indexeddb
VITE_API_URL=http://localhost:8000

.env.production:
VITE_DATA_SOURCE=api
VITE_API_URL=https://api.yourdomain.com
